# Programmatic SVG diagram system for Presentation Maker

The change replaces the planned Pexels/Unsplash stock photo approach with a fully client-side programmatic SVG diagram system. The AI now generates structured diagram data (kind, nodes, edges, sets) as part of slide JSON, a new `PresentationDiagram` React component renders ten diagram kinds as inline SVG, and the PPTX export paints equivalent shapes via pptxgenjs. The `diagram` field is defined identically in both the client Zod schema and the shared `PresentationSlideSchema`, and the AI prompt is updated to instruct the model to always populate this field on diagram-label slides.

**Watch for:** SVG marker ID collisions when multiple diagrams render on the same page (confirmed); the PPTX `paintDiagram` closure captures theme color variables from its outer scope making it silently coupled to an assumed lexical environment (confirmed); the equation-graph renderer draws a fixed decorative curve regardless of the `equation` field content (confirmed).

## High-level view

The schema is an optional `diagram` object with a discriminating `kind` field, a `nodes` array, and optional `edges`/`sets`/`equation`, constrained to max 20 nodes and 30 edges. It's `.optional()` so existing slides without diagrams remain valid.

The SVG component covers all ten kinds with dedicated render functions. The component uses a fixed `viewBox="0 0 400 280"` which means all diagrams share the same coordinate space regardless of container aspect ratio. Multiple instances on the same page will collide on SVG marker IDs.

The PPTX export handles flowchart/food-chain, Venn, and timeline with specific shape logic, then falls back to a generic labelled-box for the remaining seven kinds. Circuit, cell, cycle, water-cycle, and equation-graph lose their visual distinctiveness in the export.

The `diagram-callouts` layout code checks for `slide.diagram` and renders it when present, but the AI prompt for that layout doesn't mention the `diagram` field — only `diagramDescription` and `diagramCallouts`. The model won't populate what it isn't told about.

## SVG marker ID collisions across multiple diagram instances

Each render function that uses SVG markers defines them with static IDs: `"arrowhead"` in `renderFlowchart`, `"cycle-arrow"` in `renderCycle`, `"fc-arrow"` in `renderFoodChain`. In a standard browser DOM, SVG marker references via `url(#id)` resolve document-wide, not scoped to the enclosing `<svg>` element. When two flowcharts exist in the DOM simultaneously (presenter mode renders both the current and next slide), the second SVG's `<marker id="arrowhead">` overwrites the first's resolution. The result is arrows inheriting the wrong theme color or disappearing entirely.

The fix is to scope markers per instance. React 18's `useId()` hook or a `useMemo(() => crypto.randomUUID(), [])` gives a stable prefix:

```tsx
const uid = useId();
// then: id={`arrowhead-${uid}`} and markerEnd={`url(#arrowhead-${uid})`}
```

## PPTX export fidelity gap for non-core kinds

`paintDiagram` has three branches: flowchart/food-chain, Venn, and timeline. Everything else falls into a generic "central box with radial labels" representation. For a teacher exporting a cell diagram, the PPTX shows a plain rectangle with part names arranged in a circle — losing the cell outline, nucleus, and leader lines that the SVG renderer draws. A cycle diagram exports as a static box with labels instead of the circular flow.

If the goal is parity, cycle/water-cycle could share the flowchart branch (they're all node-sequence + edge diagrams), and cell/labelled-box could share a "central shape with leader lines" branch.

## Equation-graph renders a fixed decorative curve

`renderEquationGraph` draws:
```tsx
<path d={`M ${originX + 10} ${originY - 10} Q ${originX + axisW * 0.4} ${originY - axisH * 0.8} ${originX + axisW - 20} ${originY - axisH + 20}`}
  fill="none" stroke={theme.accent} strokeWidth="2" />
```

This is the same upward-rising curve for every equation, whether the AI provides `y = 2x + 1` or `y = sin(x)`. The `equation` string is rendered as a title but not used to compute the path. A teacher seeing "y = -x^2 + 4" as the equation label but an unrelated curve shape would find this confusing.

Two paths forward: (a) limit the prompt to say "equation-graph is illustrative; the curve shape is generic" so the AI doesn't promise something it can't deliver, or (b) implement a minimal parser that handles `y = mx + b` (line) and `y = ax^2 + bx + c` (parabola) — covering the two most common school cases.

## Prompt gap for diagram-callouts

The `diagram-callouts` layout spec in `buildSlidePrompt` says:

> "diagram-callouts" layout: populate `diagramDescription` plus `diagramCallouts: [{label, position, description?}]`

The rendering code at line ~2407 checks `slide.diagram` first and renders the `PresentationDiagram` component if present, falling back to the dashed placeholder with `diagramDescription`. But the AI is never told to populate `diagram` on this layout. The wiring exists but won't fire unless the prompt is updated.
